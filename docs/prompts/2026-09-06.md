## What was asked

The master prompt (`Claude Prompts in md/OptiStratixAI_ClaudeCode_MasterPrompt.md`)
was handed over with the instruction *"read and implement it"*.

It specified the full product build: public marketing site plus the
authenticated application, a React 18 + Vite + TypeScript frontend on a
five-token brand palette, a FastAPI + Supabase + ChromaDB backend, the nine-stage
human-in-the-loop pipeline as a first-class animated UI, a plugin-style
integration seam for teammates' separately-built feature repos, and a mandatory
`docs/` folder.

It also carried explicit guardrails: no commits or pushes, and no unilateral
structural decisions: several were reserved for the project owner.

## What was built

### Frontend: 137 files, ~14,270 lines

- **25 pages across 29 routes.** Public site (7), auth (4), app (14).
- **20 themed UI primitives** on Radix, restyled to the brand.
- **The nine-stage animated stepper**: the signature interaction. Five visually
  distinct stage states, self-drawing connectors, a travelling highlight while a
  stage runs, and a breathing butter-cream wash when the pipeline is blocked on
  a human.
- **Six chart components** on a colour palette that was *validated*, not chosen, lightness band, chroma floor, CVD separation under protanopia and
  deuteranopia, normal-vision floor and contrast, checked per mode against that
  mode's own surface. Every chart offers a table view of the same numbers.
- **Demo mode**: a real timer-driven state machine that parks at stages 5 and 7
  exactly as the server does.
- **Light/dark theming** on the same five tokens with roles swapped, applied
  before first paint so there is no flash.

### Backend: 55 files, ~5,038 lines

- **30 endpoints** (plus `/health`) mapped onto the pipeline stages.
- **The pipeline runner**, which drives automated stages and returns at 5 and 7.
- **Two storage backends** behind one interface, in-memory and Supabase.
- **12-table Postgres schema** with row-level security on every table.
- **Agent scaffolding**: one `BaseAgent` interface, five implementations,
  swappable in a single line in `registry.py`.
- **Document rendering** in Markdown, PDF and DOCX.

### Tests

- **63 frontend tests** (Vitest + Testing Library) across 10 files.
- **23 backend tests** (pytest) across 5 files.

The tests deliberately concentrate on the invariants that would fail silently:
the stage table's integrity, that the checkpoints refuse to advance, that the
Critic's output stays inspectable, and that chunking terminates.

### Docs

All nine mandatory files, each dated.

## Notable decisions and their reasoning

**The checkpoints are enforced in the runner, not the UI.** `run_from` returns
when it reaches stage 5 or 7. Two further guards refuse a gap review with
untriaged gaps, and a revision request with no notes. Putting this in the client
would have made the product's central claim a matter of good intentions.

**The Critic keeps `before` and `after` for every intervention.** "Reduces
hallucinated insights" is the project's load-bearing claim, and the Critic is the
only thing backing it. A critique nobody can inspect is worth nothing, so the
mock was written to honour the contract a live Critic must also honour, and a
test asserts it.

**Supabase client over SQLAlchemy, for a security reason.** Requests carry the
user's JWT, so Postgres RLS enforces ownership. An ORM connects as one
privileged role, which would mean every query had to remember its own ownership
filter, and one omission is a data leak.

**The human's priority sits beside the agent's, not over it.** The disagreement
between model and reviewer is exactly what this project exists to study, so it
is preserved rather than overwritten.

**Chart colour was computed, not eyeballed.** The brand palette is warm and
narrow, and the first two candidate palettes failed on chroma floor and CVD
separation. The shipped four-slot palettes were arrived at by iterating against
a validator.

## Problems hit and how they were resolved

| Problem | Resolution |
|---|---|
| `npm install` failed with `ERESOLVE` and `react-dom@undefined` on a clean tree | Installed `react` and `react-dom` first to seed resolution, then the rest |
| FastAPI refused `status_code=204` with a `-> None` return annotation | Added `response_class=Response` and returned an explicit `Response` |
| Chunking degraded to ~one chunk per character when overlap approached the window size | Clamped overlap to at most half the window |
| The Critic's mandatory measurement step pushed a plan back over the action cap it had just been trimmed to | The last optional step now gives way instead, so measurement is never the thing dropped |
| The demo project was not actually parked at checkpoint 1, its pipeline state was created empty on first read | Seeded a real parked state: stages 1, 4 complete, stage 5 awaiting a human |
| A Vitest fake-timer test deadlocked on the mock's own simulated latency | Advanced the clock past the latency before awaiting the promise |
| Two mock tests depended on each other's ordering, because resetting the pipeline clears the gaps it produced | Split them into a separate file; Vitest isolates per file |
| **The pipeline reported "7 gaps identified" while `GET /gaps` returned nothing.** Rebinding a class-level store through `self` creates an instance attribute that shadows the shared one, so the background worker's writes never reached the next request | Rebind through the class; added `tests/test_repository.py` covering the worker-writes/request-reads path. Found only by driving a real HTTP run. No unit test as written would have caught it |
| The production bundle exceeded Vite's 500 kB chunk warning | Route-level `React.lazy` with Suspense boundaries in both shells; the landing and auth pages stay eager because they are the first paint |

## What was deliberately NOT done

- **No git commit, no push, no remote touched**, per the guardrails. Everything
  is local and uncommitted.
- **No teammate feature repos integrated.** The seam is built and documented;
  the registry is empty, as instructed.
- **No live LLM calls.** All four agents are mocks. `docs/project-status.md`
  says exactly what is real and what is not.
- **No pricing content invented as if settled.** The tiers are placeholders and
  say so, in-page and in the docs.
